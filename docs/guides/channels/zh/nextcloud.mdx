# Nextcloud

连接到 Nextcloud Talk，这样您 Nextcloud 实例上的用户就可以与 Pawz 代理进行聊天。与 Mattermost 类似，Nextcloud 是自托管的——您的对话永远不会离开您的服务器。

## 安装配置

1. 在您的 Nextcloud 实例上创建一个专用的机器人用户（管理面板 → **用户**）
2. 为机器人用户生成一个 **应用密码**（用户设置 → **安全 → 设备和会话**）
3. 在 Pawz 中，转到 **设置 → 频道**
4. 选择 **Nextcloud**
5. 输入：
   - **服务器 URL** — 例如，`https://cloud.yourcompany.com`
   - **用户名** — Nextcloud 机器人用户
   - **密码** — 应用密码（不是主密码）
6. 启动此频道

## 配置

| 字段 | 必需 | 说明 |
|-------|----------|-------------|
| 服务器 URL | 是 | Nextcloud 实例 URL |
| 用户名 | 是 | 机器人账户用户名 |
| 密码 | 是 | 机器人账户的应用密码 |
| DM 策略 | 是 | 谁可以给机器人发消息（开放、白名单或配对） |
| 允许用户 | 针对白名单 | Nextcloud 用户名 |

## 工作原理

Pawz 轮询 Nextcloud Talk API 获取新消息。当机器人加入的对话中有新消息到达时，会通过代理管道进行处理——提示注入扫描 → 代理路由 → 响应 → 将回复发布回对话。

## 功能特性

- **Nextcloud Talk 对话和私信** — 机器人参与邀请它的任何对话
- **群组对话** — 当提及机器人或允许 DM 策略时，机器人可以在群聊中回应
- **每用户会话** 在对话中保持持久记忆
- **提示注入扫描** 对所有传入消息进行扫描
- **代理路由** 通过频道路由规则
- **频道特定上下文** — 精简上下文实现快速、经济的回复

## 故障排除

| 问题 | 解决方法 |
|---------|-----|
| 验证失败 | 使用 **应用密码**，而非用户的主密码。在用户设置 → 安全中生成一个。 |
| 机器人看不到消息 | 首先将机器人用户邀请到 Talk 对话中 |
| 连接被拒绝 | 验证服务器 URL 是否正确并包含 `https://`。检查 Nextcloud Talk 是否已启用。 |
| 响应慢 | Nextcloud Talk 使用轮询（非 WebSocket）。响应时间取决于轮询间隔。 |

## 提示

:::tip
- **始终使用应用密码** 而非主账户密码——更安全并且可以独立吊销。
- **机器人在受邀时加入对话** — 通过 Nextcloud UI 将其添加到特定 Talk 房间。
- **适合已在使用 Nextcloud 的组织** — 无需额外基础设施，只需添加一个机器人用户。
:::
