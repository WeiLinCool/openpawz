## 缓存令牌记账

当提供商支持提示缓存时(如Anthropic)，Pawz对缓存令牌应用较低的费率：

| 令牌类型 | 费用倍数 |
|------------|----------------|
| 正常令牌 | 100％(全价) |
| 缓存读取 | **正常代价的10%** |
| 缓存创建 | **正常代价的25%** |

:::tip
Anthropic的提示缓存可以显著降低重复任务的成本。长系统提示和技能指令最能从缓存中受益，因为它们在回合中保持不变。
:::

## 每日预算

Pawz可以强制执行每日支出限额以防止失控成本。

### 配置

| 设置 | 默认 | 描述 |
|---------|---------|-------------|
| `daily_budget_usd` | `$10.00` | 所有模型的每日最大支出 |

设置为`0`以完全禁用预算执行。

在**设置 → 智能体默认设置**中配置预算或直接在引擎配置中配置：

```json
{
  "daily_budget_usd": 10.0
}
```

### 预算执行

**每次API调用前**都会检查预算。随着支出增加，Pawz提供逐步警告：

| 阈值 | 行动 |
|-----------|--------|
| **50%** 预算 | 警告通知 |
| **75%** 预算 | 提升警告 |
| **90%** 预算 | 紧急警告 |
| **100%** 预算 | **硬阻止** — 拒绝API调用 |

:::警告
当日预算达到时，所有AI API调用都被阻止，直到第二天(协调世界时中午)。正在进行的对话将停止收到响应。设置一个与预期每日使用量相符的预算。
:::

## DailyTokenTracker

Pawz通过`DailyTokenTracker`维持每模型成本跟踪：

- 按每个模型分别跟踪输入和输出令牌
- 使用上述价格表计算成本
- 自动应用缓存令牌折扣
- 每天午夜重置

跟踪器启用预算执行系统，并为聊天界面中的成本显示提供支持(在带有用量统计的`complete`事件中显示)。

## 自动模型等级选择

`auto_tier`特性基于复杂性自动将任务路由到更便宜或更昂贵的模型。

### 任务复杂性分类

Pawz分析每条消息以确定其是简易还是复杂：

| 分类 | 路由 | 任务示例 |
|----------------|---------|---------------|
| **简易** | 路由到`cheap_model` | "现在几点了?"，"将5公斤转换为磅"，简单问答 |
| **复杂** | 路由到`default_model` | 多步骤推理，代码生成，研究 |

分类使用关键字信号和启发式方法来决定。当您的模型路由配置中启用`auto_tier`时，简易消息完全跳过昂贵的默认模型。

### 模型路由配置

```json
{
  "model_routing": {
    "boss_model": "claude-opus-4-6",
    "worker_model": "claude-sonnet-4-6",
    "cheap_model": "claude-3-haiku",
    "auto_tier": true,
    "specialty_models": {
      "coder": "gemini-2.5-pro"
    },
    "agent_models": {
      "agent-uuid-here": "gpt-4.1"
    }
  }
}
```

| 字段 | 描述 |
|-------|-------------|
| `boss_model` | 编排者/老板智能体的强大模型 |
| `worker_model` | 子智能体的默认模型(更便宜/更快) |
| `cheap_model` | 当`auto_tier`开启时用于简易任务的预算模型 |
| `auto_tier` | 启用按任务复杂性进行自动模型选择 |
| `specialty_models` | 针对专业领域的覆盖(例如，`coder`，`researcher`) |
| `agent_models` | 针对单个智能体的覆盖(最高优先级) |

**解决顺序** (优先级从高到低):
1. 单智能体覆盖(`agent_models`)
2. 针对专业覆盖(`specialty_models`)
3. `cheap_model`(如果`auto_tier`启用且任务被标记为简易)
4. `default_model`

## 成本优化建议

:::tip 成本优化策略

1. **使用`auto_tier`**: 启用自动模型选择，使简单查询使用便宜模型。这项功能本身就能节省50%以上成本。

2. **设置每日预算**: 即使宽裕的预算也能防止由自动化任务或定时作业引起的意外失控成本。

3. **为开发使用Ollama**: 本地模型免费。在切换到付费提供商之前使用它们来测试智能体配置。

4. **匹配模型到任务**: 对简单问题不使用Claude Opus。创建聊天模式(见[锻造厂](/foundry.md))以适应不同级别。

5. **启用会话压缩**: 长会话每轮消耗更多令牌。使用`/compact`或让自动压缩管理上下文大小。

6. **利用提示缓存**: Anthropic的缓存读取仅花费正常输入令牌的10%。一致的系统提示和技能指令获益最多。

7. **使用`worker_model`进行编排**: 在多智能体项目中，老板智能体应该使用强大模型，但工作者可以使用更便宜的替代方案。

8. **监控`complete`事件**: 每个回应包括令牌用量统计(输入/输出/总令牌和模型名称)，以便您可以实时跟踪支出。

:::
