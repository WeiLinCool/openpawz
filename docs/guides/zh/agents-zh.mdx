# 智能体

智能体是 Pawz 的核心——能够聊天、使用工具、记住上下文并进行协作的自主 AI 角色。

## 创建智能体

1. 在侧边栏中找到“智能体”

2. 点击“创建智能体”

3. 填写基本信息：

- **名称** — 显示在聊天窗口和 Dock 栏中

- **头像** — 从 50 个精灵头像中选择

- **颜色** — 从 7 种强调色中选择

- **简介** — 简要描述此智能体的功能

## 模板

模板预先配置了常见用例的技能和个性：

| 模板 | 技能 | 语气 | 主动性 | 细节 |

|----------|--------|------|------------|--------|

| **通用** | 网络搜索、网页抓取、阅读、写作 | 平衡 | 平衡 | 平衡 |

| **研究** | 网络搜索、网页抓取、阅读、写作、浏览器 | 正式 | 主动 | 全面 |

| **创意** | 网络搜索、网页抓取、阅读、写作 | 随意 | 主动 | 平衡 |

| **技术** | 网络搜索、网页抓取、阅读、写作、执行、编辑 | 平衡 | 被动 | 全面 |

| **自定义** | 您选择 | 您选择 | 您选择 | 您选择 |

## 个性设置

每个代理都有三个个性维度：

| 维度 | 选项 | 描述 |

|------|---------|-------------|

| **语气** | 随意 / 平衡 / 正式 | 代理的语气 |

| **主动性** | 被动 / 平衡 / 主动 | 代理在未被要求的情况下所做的事情 |

| **细节** | 简明 / 平衡 / 全面 | 回复的长度和深度 |

## 模型选择

每个智能体可以使用不同的模型：

- **默认** — 使用引擎的默认模型

- **特定模型** — 从常用模型目录中选择或输入任意模型名称

常用模型包括：

- **Gemini**：gemini-2.5-pro、gemini-2.5-flash、gemini-2.0-flash

- **Anthropic**：claude-sonnet-4、claude-haiku-4、claude-opus-4

- **OpenAI**：gpt-5.1、gpt-4.1、gpt-4.1-mini、o3、o4-mini

## 技能

切换智能体可以使用的工具：

`web_search` · `web_fetch` · `browser` · `read` · `write` · `exec` · `image` · `memory_store` · `cron` `消息`

请参阅[技能指南](/skills)以获取完整的技能库。

## 灵魂文件

每个代理都有三个 Markdown 文件来定义其身份：

| 文件 | 用途 |

|------|---------|

| **IDENTITY.md** | 名称、表情符号、氛围、头像描述 |

| **SOUL.md** | 个性、沟通风格、界限 |

| **USER.md** | 用户身份、偏好、称呼方式 |

其他标准文件：

- **AGENTS.md** — 操作规则、优先级、内存使用情况

- **TOOLS.md** — 关于本地工具和约定的说明

在代理详情视图中编辑这些文件。更改将在下一条消息中生效。

### 灵魂文件自动填充

创建新代理时，Pawz 会自动填充其灵魂文件，以便代理从第一次对话开始就知道自己的身份。种子生成过程只会写入**尚不存在**的文件，因此您的编辑永远不会被覆盖。

自动填充的文件如下：

| 文件 | 填充内容 |

|------|----------------|

| **IDENTITY.md** | 代理名称、ID、角色/简介、专长（来自模板）、性格轴、界限以及任何自定义系统提示 |

| **SOUL.md** | 引导代理使用 `soul_write` 开发自身声音的初始模板 |

| **USER.md** | 引导代理通过 `soul_write` 记录用户偏好的初始模板 |

:::提示

Soul 文件存储在 `agent_files` 数据库表中，键为 `(agent_id, file_name)`。每个代理除了三个默认文件外，还可以拥有任意数量的附加文件——代理可以在对话过程中使用 `soul_write` 工具创建自己的文件。

:::

对于由编排器创建的代理（后端代理），Soul 文件会在下次应用加载时自动填充。 `IDENTITY.md` 文件包含代理在项目中被分配的角色和专长。

## 后端代理

除了手动创建的代理（存储在 `localStorage` 中）之外，Pawz 还支持由编排器在规划项目时以编程方式创建的**后端代理**。

### 存储模式

后端代理存储在 `project_agents` SQLite 表中：

| 列 | 类型 | 描述 |

|--------|------|-------------|

| `project_id` | 文本 | 此代理所属的项目 |

| `agent_id` | 文本 | 代理的唯一标识符 |

| `role` | 文本 | 代理在项目中的角色（例如 `worker`、`boss`） |

| `specialty` | 文本 | 此代理擅长的领域（见下文） |

| `status` | 文本 | 当前状态（`idle`、`busy` 等） |

| `current_task` | 文本 | 代理当前正在处理的任务 |

| `model` | 文本 | 此代理的覆盖模型（可选） |

| `system_prompt` | 文本 | 自定义系统提示（可选） |

| `capabilities` | 文本 | 以逗号分隔的工具功能列表 |

### 专业领域

当协调器为项目创建代理时，它会为每个代理分配一个专业领域：

| 专业领域 | 描述 |

|-----------|-------------|

| `coder` | 编写和编辑代码 |

| `writer` | 散文、文档、文案 |

| `analyst` | 数据分析和解释 |

| `researcher` | 信息收集和综合 |

| `designer` | UI/UX 和视觉设计 |

| `tester` | 测试和质量保证 |

| `reviewer` | 代码审查和反馈 |

| `planner` | 项目规划和协调 |

| *(自定义)* | 任意自由格式的特殊字符串 |

:::信息

后端代理会在代理网格中显示“AI 创建”徽章。它们会在加载时合并到本地代理列表中，并自动获得独特的精灵头像。它们的名称源自 `agent_id`，连字符替换为空格并采用首字母大写格式。

:::

## 代理级历史记录

当多个代理共享会话时（例如，在编排或代理间委托期间），每个代理只能看到与其自身上下文相关的消息。对于非默认代理，`agent_send_message` 和 `agent_read_messages` 的跨代理工具结果会被过滤掉。

这可以防止上下文污染——一个代理的委托结果不会干扰另一个代理的对话流程。编排主代理可以看到所有消息（未经过滤），以保持完整的态势感知。

## 代理策略

代理策略控制代理可以使用的**哪些工具**。这使您可以创建只能读取文件的受限代理，或可以执行 shell 命令的完全授权代理。

### 策略模式

| 模式 | 行为 |

|------|-----------|

| **允许列表** | 仅允许使用明确列出的工具（最严格） |

| **拒绝列表** | 所有工具均可用，*但*明确拒绝的工具除外 |

| **无限制** | 无限制 — 允许使用所有工具（默认） |

### 工具分类

Pawz 将内置工具分为两类：

**安全工具**（只读，低风险）：

```

read_file、list_directory、web_search、web_read、

memory_search、soul_read、soul_list、self_info、fetch

```

**高风险工具**（修改系统或向外部发送数据）：

```

exec、write_file、delete_file、append_file、

email_send、webhook_send、rest_api_call、slack_send、

github_api、image_generate、soul_write、update_profile、

create_agent、create_task、manage_task

```

### 策略预设

提供四个预设，方便快速设置：

| 预设 | 模式 | 描述 |

|--------|------|-------------|

| **无限制** | `unrestricted` |完全访问所有工具（默认）|

| **标准** | `拒绝列表` | 所有工具可用，但高风险工具需要人工审核批准 |

| **只读** | `允许列表` | 仅限安全读取/搜索工具 — 禁止修改 |

| **沙箱** | `允许列表` | 仅限网页搜索和内存访问 — 禁止文件或执行访问（`web_search`、`web_read`、`memory_store`、`memory_search`、`self_info`）|


### 其他策略选项

| 设置 | 说明 |

|---------|-------------|

| `requireApprovalForUnlisted` | 在允许列表模式下，未列入列表的工具仍可运行，但需要人工批准 |

| `alwaysRequireApproval` | 无论在何种模式下，*始终*需要批准的工具列表 |

| `maxToolCallsPerTurn` | 限制代理在单回合内可调用的工具数量 |

:::注意

策略存储在每个代理的 `localStorage` 中，键名为 `paw_agent_tool_policies`。清除浏览器存储会将所有策略重置为默认值（无限制）。

:::

## 头像系统

Pawz 内置 **50 个像素风格的头像**，采用 20 世纪 80 年代的日式风格。这些精灵图是 96×96 像素的 PNG 文件，位于 `src/assets/avatars/1.png` 到 `src/assets/avatars/50.png` 目录下。

- 创建代理时会随机分配一个头像（1-50）。

- 头像以数字字符串（例如 `"5"`）的形式存储在代理的 `avatar` 字段中。

- 您可以随时在编辑视图中更改代理的头像。

- 旧版表情符号头像会在加载时自动迁移为精灵图头像。

- 后端代理会根据其专业领域分配头像：程序员 → `10`，研究员 → `15`，设计师 → `20`，沟通员 → `25`，安保人员 → `30`，普通员工 → `35`，作家 → `40`，分析师 → `45`。

提示：Pawz 代理默认使用头像 `5`。如果您想快速按专业领域识别客服人员，后台客服人员会根据其角色分配主题化的角色编号。

:::

## 客服人员面板

面板位于屏幕右下角，是一个浮动托盘：

- 显示所有客服人员的圆形头像

- 点击头像即可打开**迷你聊天**弹出窗口

- 未读消息徽章显示新消息

- 使用切换按钮展开/折叠面板

- 鼠标悬停时，工具提示会显示客服人员姓名

## 迷你聊天

每个客服人员都有一个类似 Messenger 的聊天窗口：

- 从面板弹出

- 实时流式回复

- 完整的工具执行流程，包含审批流程

- 每个客服人员拥有独立的会话

- 拖动即可重新定位

## 系统提示

高级用户：完全覆盖客服人员的系统提示。这将替换所有自动生成的指令。当您需要完全控制时，请使用此功能。

## 权限限制

添加代理必须遵守的自定义规则，例如：

- “绝不共享 API 密钥”

- “删除文件前务必先征得同意”

- “回复字数限制在 200 字以内”
