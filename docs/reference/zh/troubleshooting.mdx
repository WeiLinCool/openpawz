# 故障排除

常见问题及解决方案。

## 构建问题

### Rust 编译失败

**现象：** `cargo build` 错误，缺少系统依赖

**修复：**
```bash
# Ubuntu/Debian
sudo apt install -y libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf libssl-dev

# macOS
xcode-select --install
```

### Node.js 错误

**现象：** `pnpm install` 失败，版本不匹配

**修复：** 确保 Node.js 18+ 和 pnpm 已安装：
```bash
node --version  # 应为 18+
pnpm install
```

## 提供商问题

### "未配置提供商"

**现象：** 智能体无法响应，无可用模型

**修复：** 在 **设置 → 提供商** 中至少添加一个提供商。

### 提供商返回错误

**现象：** 计费、身份验证或速率限制错误

**修复：**
1. 检查您的 API 密钥是否有效
2. 检查您的账户是否有信用额度
3. 添加第二个提供商以实现自动故障转移

### Ollama 未检测到

**现象：** Pawz 未看到本地 Ollama

**修复：**
```bash
# 检查 Ollama 是否正在运行
curl http://localhost:11434/api/tags

# 启动 Ollama
ollama serve
```

### 未找到模型

**现象：** "未找到模型" 错误

**修复：**
```bash
# 对于 Ollama — 拉取模型
ollama pull llama3.1

# 对于云提供商 — 检查确切的模型名称
```

## 内存问题

### 嵌入失败

**现象：** 内存搜索返回无结果，嵌入错误

**修复：**
```bash
# 确保嵌入模型已安装
ollama pull nomic-embed-text

# 检查 Ollama 是否正在运行
curl http://localhost:11434/api/tags
```

### 旧内存没有嵌入

**现象：** 嵌入设置之前创建的内存不出现在搜索结果中

**修复：** 在记忆宫殿中使用 **回填** 按钮为所有内存添加回溯嵌入。

## 通道问题

### 通道无法连接

**现象：** 通道状态保持 "断开连接"

**修复：**
1. 验证机器人令牌是否正确
2. 检查网络连接
3. 确保机器人在平台上具有适当的权限
4. 检查 Pawz 日志以获取错误详情

### 消息被阻止

**现象：** 某些消息无法通过

**原因：** 提示注入扫描器阻止了具有 `critical` 严重性的消息。

**修复：** 这是正常功能 — 这些消息包含了注入模式。检查日志以查看被阻止的内容。

### 机器人未在群组中响应

**现象：** 机器人可在私人消息中工作但在群聊中无效

**修复：**
- **Telegram:** 在 @BotFather 中禁用群组隐私
- **Discord:** 确保机器人有权 "读取消息历史记录"
- **Slack:** 使用 `/invite @bot` 将机器人邀请到频道

## Docker 沙箱

### "Docker 不可用"

**现象：** 容器沙箱失败

**修复：**
```bash
# 检查 Docker 是否正在运行
docker info

# 在 Linux 上，确保您的用户属于 docker 组
sudo usermod -aG docker $USER
```

### 容器超时

**现象：** 命令达到超时限制

**修复：** 在 **设置 → 高级 → 容器沙箱** 中增加超时。

## 性能

### 响应缓慢

**原因：**
1. **大型上下文** — 使用 `/compact` 总结较早的消息
2. **过多内存** — 在内存设置中减少 `recall_limit`
3. **慢模型** — 切换到更快的模型 (gpt-4o-mini, gemini-2.0-flash)
4. **CPU 上的 Ollama** — 使用较小模型或获得GPU

## 聊天气氛行为

### 智能体不断重复相同的失败方式

**现象：** 智能体重复尝试同一个故障的工具调用。

**Pawz 的处理方式：** 失败的工具交互在每个回合前自动从上下文中删除，因此智能体在重试时能有一个干净的开端。如果您仍然看到循环，智能体可能遇到了真正的功能限制。

**修复：**
1. 发送一条带有更具体指令的新消息
2. 尝试推理能力更强的不同模型（如 Claude Sonnet 4、Gemini 2.5 Pro）
3. 使用 `/new` 启动一个具有完全崭新上下文的新会话

### 我可以在智能体工作时发送消息吗？

**可以。** Pawz 自动排队您的消息。活跃的智能体在下次工具调用边界处完成，然后处理您队列中的消息。您无需等待响应即可输入。

### 高内存使用

**修复：**
- 在 **设置 → 引擎** 中减少 `max_concurrent_runs`
- 使用较小的模型
- 关闭未使用的浏览器配置文件

## 日志

检查 Tauri 日志以获取详细的错误信息：

```bash
# Linux
~/.local/share/com.openpawz.openpawz/logs/

# macOS
~/Library/Logs/com.openpawz.openpawz/
```

在任意聊天中使用 `/debug` 切换调试模式以输出详细信息。

使用 `/status` 查看当前引擎配置和提供商状态。
